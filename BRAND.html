Fenix Eval

品牌规格

给前台、后台、README、图表和错误文案对齐用。各节先图后解释。产品事实以需求文档为准。不改契约，不编造分数。不是营销页。

§1

名称

对外产品名：Fenix Eval（两词、首字母大写、中间空格）。中文里直接写 Fenix Eval，不要译成「凤凰评测」「飞尼克斯」。不要单独用「Fenix」指这个产品。

长文档里第一次出现，可以括注功能通称：Fenix Eval（评测展示服务）。通称可以和产品名一起用，不能互相替换。

位置写法
产品名Fenix Eval
前台页脚署名先写 Fenix Eval，再写不混榜、未报告用量。不要写成 Harbor Hub 或官方榜
代码标识符eval-display、EVAL_DISPLAY_*、Go module evo-harness 不要改。品牌名不要倒灌进环境变量或 Harbor 路径

不要用这些当界面名：FenixEval；FENIX EVAL；Fenix-Eval；eval-display（作用户可见产品名）。

§2

一句话身份

Fenix Eval 收录已经跑完的 Harbor 作业，按 job_id 列出我方榜、完成度和用量。它不是官方 DeepSWE 排名。

完成度 = 该作业已入库 trial 的 reward 均值（只有 0 或 1）。用量 = token、成本、步数五个字段，接口里始终出现。

给技术组长和评测执行用：判断私有模型接入 AOS 之后，问题在 AOS 还是客户侧。也可以给 COS 优化和 AOS 引擎背书提供可引用的对照。

第 1 层先做到：有 job/trial id 可查、Pass@1 可复算、用量字段始终出现。Harbor JSON 里没有的 GPU × 引擎消耗、COS 档位、AOS 编排路径，界面不要猜。不要发明 token、cost、步数、ROI 或 COS SKU。

§3

相对 Harbor / Pier / DeepSWE 的位置

名称它是什么本产品怎么叫
Harbor评测 runner；官方 CLI 执行和 upload兼容上传入口，不是第二套 runner。不调用 harbor run，不复刻 Hub
Pier一种执行器；对照包由它产出 Harbor 目录写在 overlay 的 runner 里。不要把 Pier 说成本产品
DeepSWE 官网榜Pier + mini-swe-agent + Modal，另一套协议不可比。Harbor / Peri / COS 作业的完成度不能写成该榜成绩
Fenix Eval我方结果面：ingest、S3、SQLite、读接口、后台 overlay「我方榜」。分数按已入库 trial 自算

Harbor 作业和官方 Pier / DeepSWE 榜不可比。不要把这边的完成度写成那边的成绩。

对照包 deepswe-peri-3142 只用来验收 ingest。69/113、20/44 是该包的实测聚合，不是产品承诺，也不是 Pier 官方榜。对外引用要带 id，并注明不是 Pier 官方算法。incomparability 用来写清为什么不可比，不用来抬高分数。

§4

语气

官方语气：严谨，但不晦涩。

严谨

  1. 用书面语。不推销，不用「赋能」「一站式」「领先」。
  2. 术语固定：完成度、未报告用量、榜单、harness。
  3. 缺省填的 0 不要写成测得 0。未报告就写未报告；不可比就写不可比。
  4. Harbor 作业与官方 Pier / DeepSWE 榜不可比。禁止混榜。
  5. 完成度的分母是已入库 trial。榜单均值是各作业完成度的算术平均，不是把 trial 混在一起再算。

不晦涩

  1. 句子短。先说结论，再补限定。
  2. 必要术语第一次出现，用一句人话解释。例如：完成度 = 该作业已入库 trial 的 reward 均值。
  3. 少用「之 / 其 / 所谓」和绕弯的长从句。
  4. 图表和表的规则写成「要这样做 / 不要那样」，不要写成论文摘要。
  5. 规格板和界面：先图后解释。宽屏图在左、说明在右，不要让右栏空着。

错误文案示例：后台令牌无效或未填写。 Harbor 面保留 PGRST202 等 CLI 标识。后台删除要写清不可恢复。不要用「Oops」。

§7

做 / 不做

做不做
  • 用户可见名称用 Fenix Eval。契约仍写 Harbor 兼容、S3/RustFS、SQLite。
  • 文案严谨但不晦涩：术语固定，句子短，必要术语先用人话解释。
  • 图和文案一起说清：完成度怎么算、横轴向右更少、空心点是未报告、不混榜。规格板先图后解释。
  • 用量五个字段始终出现。未报告和测得的 0 用 usage_reported 区分。
  • 引用数字时带 id，并写清不可比。后台区分「尚未 finalize」和「已在榜」。
  • 自称官方 Pier / DeepSWE 榜，或把 Harbor 作业和官网榜排在一起。
  • 发明 token、cost、步数、ROI，或用其它 job 均值、草稿 HTML 示意值去填。
  • 发明 COS SKU、GPU 消耗、引擎质量评语。
  • 把 peri-3142-full 和 fail44 合成一行。
  • 用「效果」代替完成度；把缺省 0 写成测得零消耗。
  • 营销口吻、吉祥物、为品牌去改 EVAL_DISPLAY_*。
  • 点旁常驻分数气泡、糖果阴影、斑马纹表、用品牌蓝给点上色。
  • 把本页示意图点位或表行当成实测或官方榜。

§8

图表

首页散点叫「完成度对照」。完成度 = 该作业已入库 trial 的 reward 均值。以后同类型的图也按本节做。图 6、图 7 的点是编的，不要当成 Harbor / Fenix 实测，不要抄官方榜或对照包 69/113、20/44，不要发明 COS SKU。

要这样做

  1. 纵轴是完成度，向上更高。刻度写成百分数。
  2. 横轴是 step / cost / token，方向反过来。原始值向右更少，所以右上更好。step 用步数，cost 用美元，token 用三个 token 字段相加。
  3. 颜色表示 harness，一个点表示一对 model + harness。harness 就是 agent。主题蓝不要拿来给点上色。
  4. 详情只在悬停时出现。不要在点旁边常驻分数。
  5. 未报告用量画空心方点，落在最右边。写「未报告用量」，不要写成测得 0。
  6. 一图只画当前榜单。peri-3142-full 和 fail44 必须分开画。
  7. 方点、1px 浅灰网格、没有阴影。更优区只用绿底 #2f9e44、约 12% 透明。图例放在图外右侧。
  8. 悬停卡片：白底、细线、没有阴影。未报告时写清：下面的 0 是源没给，不是测得的 0。
  9. X 轴分段（step / cost / token）选中时用主题蓝底白字。这是控件，不是点的颜色。

不要那样

  • 不要用「效果」当轴名。不要按完成度做颜色渐变。
  • 不要混榜。不要用点的大小表示 trial 数。不要加趋势线或动画。
  • 不要软阴影、圆角糖果点、虚线仪表盘网格。不要用品牌蓝铺更优区。

§9

表格

前台作业表和后台列表按本节做。表是用来读数的，不是仪表盘卡片。白底、灰线、紧凑、直角。蓝只用在可点击的地方。图 8 与线上榜单表同一套列：勾选、作业、harness、model、完成度、用量、签字、执行器。三行和图 6 是同一套编出来的作业，不要当成实测榜。

要这样做

  1. 列和线上榜单表对齐：对照勾选、作业（名 + id）、harness、model、完成度、trial 数、用量五个字段、签字、执行器。榜单名称只出现在页顶标签，不要每行重复。
  2. 未报告用量不要单开列：数字仍显示 0，格子里标「未报告」。
  3. 文本左齐，数字右齐。表头浅灰，行间 1px 细线。悬停用极浅灰 #f3f5f7。选中行加 2px 蓝左边线。
  4. 空态写一句人话，不要插画。前台：「还没有已完成且未隐藏的作业。请用 Harbor CLI 上传后再刷新。」
  5. 一行一个 job_id。表只含当前榜单。后台删除按钮用 #9b2c2c。

不要那样

  • 不要斑马纹，不要用半透明蓝铺行。
  • 不要把 peri-3142-full 和 fail44 合成一张表。
  • 未报告时不要删列、不要改成「—」、不要写成「测得 0」。
  • 完成度不要用粗进度条。不要给表加卡片阴影。
